# Как вносить изменения

Ветка `main` — это то, что работает на сервере для всех пользователей: Amvera разворачивает её сам после каждого слияния. Поэтому в `main` ничего не пушится напрямую — только через pull request.

## Порядок работы
1. Обнови проект: `git checkout main && git pull`.
2. Создай ветку под свою задачу: `git checkout -b moya-zadacha`.
3. Запусти проект локально (см. README, «Локальный запуск») и внеси изменения.
4. Перед пушем прогони все проверки — они же запускаются на GitHub:
   ```
   python tests/run_ci.py
   ```
   Всё должно быть зелёным. Для новой возможности добавь тест в `tests/` и подключи его в `tests/run_ci.py`.
5. Запушь ветку и открой pull request в `main`, заполни шаблон.
6. Дождись зелёной галочки CI и одобрения владельца. После слияния сервер обновится сам.

## Что нельзя
- Добавлять в репозиторий ключи, пароли, токены, `.env`, файлы баз данных (`*.db`), `catalog_seed.json`. CI проверяет это и не пропустит.
- Менять `amvera.yml`, `Dockerfile`, `.github/`, `server/auth.py` и логику прав администратора без отдельного обсуждения с владельцем.
- Пушить в `main` напрямую и делать `git push --force`.

## Если что-то сломалось
Не паникуй: можно откатить слияние (`Revert` на странице pull request) — сервер вернётся к прежней версии. Данные пользователей лежат на сервере отдельно от кода и от откатов не страдают, а резервные копии базы делаются раз в сутки (README, «Резервные копии»).
